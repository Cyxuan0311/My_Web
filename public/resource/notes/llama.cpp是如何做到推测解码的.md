llama.cpp 中的推测解码，代码实现上是一个设计精巧的模块化系统。它的核心思路是，在**不修改核心模型架构**的前提下，通过一个统一的调度器，将“起草（Draft）”和“验证（Verify）”两个阶段串联起来，并利用批量处理（batching）来加速。

### 🧩 整体架构：模块化的“起草-验证”流水线

其代码实现围绕几个关键模块构建：

*   **统一的调度器**：位于 `common/speculative.cpp` 和 `common/speculative.h` 中。它负责任务的生命周期管理，如生成草稿（`common_speculative_draft`）和处理验证结果（`common_speculative_accept`）。
*   **多样的起草策略**：`llama.cpp` 支持多种起草方式（详见下文），通过 `--spec-type` 参数指定。
*   **核心验证引擎**：目标模型（Target Model）以**批量模式**（batch mode）一次性处理所有草稿token，实现高效验证。
*   **状态管理**：对于有状态（如RNN）或混合架构模型，需要保存和恢复KV Cache等中间状态。

### ⚙️ 起草策略：多种实现方案

`llama.cpp` 实现了多种起草策略，代码实现各有不同，以适应不同场景。

| 策略类型 | 实现方式 | 关键代码/参数 |
| :--- | :--- | :--- |
| **外部草稿模型 (Draft Model)** | 使用一个独立的、更小的模型（如 `Qwen2.5-32B` 搭配 `Qwen2.5-0.5B`）来生成草稿。 | 通过 `--model-draft` 参数指定草稿模型路径。 |
| **MTP (Multi-Token Prediction)** | 利用模型内置的“MTP头”（一个额外的Transformer层），直接从主模型的隐藏状态预测后续token。 | 实现涉及 `src/models/qwen35.cpp` 等文件，需要特定的模型权重支持。 |
| **EAGLE** | 一种更先进的编码器-解码器架构。它从目标模型提取特征，压缩后用于快速生成草稿。 | 在 `src/models/eagle3.cpp` 中实现，通过 `--eagle3` 标志启用。 |
| **n-gram 缓存** | 基于历史token的n-gram统计信息来生成草稿。 | 通过 `--spec-type ngram-cache` 启用。 |
| **n-gram 映射** | 在已生成的token历史中查找重复模式来预测后续内容。 | 通过 `--spec-type ngram-simple`或 `ngram-map-k`启用。 |

> **注意**：`n-gram` 系列方法**不需要额外的模型**，完全基于已生成的上下文进行预测，非常轻量。

### 🔄 核心流程：代码中的“猜测与验证”

以下是推测解码在代码层面的核心执行流程：

1.  **初始化**：调度器根据 `--spec-type` 等参数初始化相应的起草策略和状态。
2.  **生成草稿 (Draft)**：调度器调用起草模块（如 `common_speculative_draft`），生成一个包含多个token的序列。
3.  **批量验证 (Verify)**：将“已有上下文 + 草稿token序列”作为一个**批量请求**喂给目标模型。目标模型会并行计算所有token的概率。
4.  **接受与回滚 (Accept & Rollback)**：调度器（`common_speculative_accept`）将目标模型的输出与草稿对比，确定最长连续匹配的token数（`n_accepted`）。
    *   **接受**：将匹配的token加入生成序列。
    *   **拒绝**：丢弃第一个不匹配的token及其后的所有草稿token，并将目标模型计算的正确token加入序列。
5.  **状态更新**：更新KV Cache等内部状态，为下一轮迭代做准备。

### 🚀 关键优化技术

*   **批量处理**：将验证多个token的计算合并为一次前向传播，是加速的核心。
*   **CUDA Graph**：用于将一批固定的计算操作优化为一个GPU可执行图，以减少内核启动开销。但在推测解码中，验证阶段的token数量可能动态变化，可能导致CUDA Graph无法启用，影响性能。
*   **高效状态管理**：对于复杂模型，使用 `ggml_backend_tensor_copy_async()` 等API在GPU间异步复制状态，避免通过CPU中转，减少延迟。

### 💎 总结

`llama.cpp` 的推测解码，本质上是一个**高度模块化的、基于批量验证的调度框架**。它通过清晰的接口将多样的“起草策略”与核心的“验证引擎”解耦，让开发者可以灵活地组合不同的技术来加速推理，同时也在底层通过CUDA Graph、高效状态管理等手段挖掘极致性能。
