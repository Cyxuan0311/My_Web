**SSH（Secure Shell）本身就是一个应用层网络协议**，它基于 **TCP/IP 传输层协议** 运行。

更具体地说，可以从以下几个维度来理解：

### 1. 传输层依赖（底层基石）
SSH 协议在传输层**强烈依赖 TCP 协议**（通常使用默认端口 **22**）。它不采用 UDP，因为 SSH 需要可靠的、有序的数据传输来保证加密会话的完整性（TCP 的重传和确认机制对此非常重要）。

你在 VS Code 报错中看到的 `connect to host ... port 8022: Connection refused`，本质上就是 **TCP 三次握手失败**（端口没开或 IP 不对），这时 SSH 应用层的协议甚至还没开始运作。

### 2. 协议内部架构（三层结构）
SSH 不仅仅是一个简单的协议，它是一个**三层架构的协议族**：

-   **传输层协议（The Transport Layer）**：负责在客户端和服务器之间建立安全的通道。它处理**密钥交换**（如 Diffie-Hellman）、**公钥认证**（验证服务器身份）以及**数据加密与完整性校验**（如 AES 加密、SHA 哈希）。这一层保证了数据在传输过程中是加密且未被篡改的。
-   **用户认证协议（The User Authentication Protocol）**：运行在传输层之上，负责验证客户端的身份。它支持多种认证方式，包括**密码**、**公钥**（RSA/ECDSA）、键盘交互等。
-   **连接协议（The Connection Protocol）**：这是最高层，它将前面建立好的单一加密通道**复用（Multiplex）** 成多个逻辑通道。正因为这一层，同一个 SSH 连接可以同时支持远程 Shell 命令执行、文件传输（SFTP）、端口转发（隧道）等多种功能。

### 3. 安全模型（C/S 架构）
SSH 采用经典的**客户端-服务器（C/S）模型**。其核心安全依赖于**非对称加密**（公钥体系）进行身份验证和密钥交换，利用**对称加密**进行后续海量数据的快速加密传输。

---

**结合你刚才的问题：**
你之前尝试用 VS Code 连接时报 `Connection refused`，这发生在 **TCP 层**。也就是说，你的电脑（客户端）还没来得及向平板的 8022 端口发送任何 SSH 加密握手包，就直接被网络层或操作系统拒绝了。因此，排障的重心依然要放在**检查 `sshd` 进程是否真的在监听 8022 端口**，以及平板的 IP 地址是否正确上。
